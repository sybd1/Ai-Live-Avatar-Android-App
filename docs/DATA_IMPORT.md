# 공식 공고 등록 기준

현재 `data/programs.json`에는 사용자가 승인한 실제 프로그램 ‘따뜻한 집’ 1건이 있다. 공식 목록에서 확인한 범위만 등록했으며, 확인되지 않은 준비물·시간·순서·자격은 비워 두었다. 상세 출처는 `data/warm-home-source.md`에 있다.

```powershell
.\scripts\import-programs.ps1 -File P:\data\programs.json
```

서버 JAR를 빌드한 뒤 실행한다. API 키를 파일에 넣지 않는다. 동일 버전 ID의 내용을 바꾸면 등록을 거절한다. 공고가 변경되면 새 버전 ID로 등록하고, 기존 버전은 보존한다. 온통청년 자동 동기화는 인증키 발급과 명세 검증 전까지 비활성이다.

운영자가 공식 공고·회차를 검토한 후 다음 값을 등록한다.

- 불투명 UUID인 프로그램·버전·회차·근거 ID.
- 공식 제목·기관·원문 URL·게시일·확인일·원문 해시.
- 모집 상태와 시작/마감의 정밀도(date 또는 datetime).
- 자격 조건과 각 조건의 공식 인용.
- 장벽 지표 다섯 개. 알려지지 않은 값은 null이며 0으로 넣지 않는다.
- 타임라인·준비물의 사실 ID·인용·페이지/절. 순서가 없으면 orderIndex는 null.
- 회차별 실제 주소·좌표의 검증 여부. 기관 본부 주소로 대체하지 않는다.

게시 전 원문 인용과 값·부정 표현을 대조한다. 가상 공고는 `synthetic=true`인 별도 테스트 자료로 구분하고 실제 모집 목록에서 제외한다. 일반 앱에서 공고를 작성·수정하는 엔드포인트를 제공하지 않는다.
