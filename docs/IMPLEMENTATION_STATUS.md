## 최신 스트리밍·성능 결과

- 가상 음성 한 건의 새 Live 중계 검사에서 연결 준비 약 1.1초, 발화 종료 후 첫 서버 PCM 약 **1.4초**를 확인했다. 이후 공식 활동 날짜 질문은 등록된 검증 근거와 별도 WAV로 답했고, 정책 답변 중 가상 음성 조각이 섞이지 않았다. `.tools/live-stream-check.json`. 표본 1건의 서버 도착 시간이며 휴대폰의 실제 재생 시작 지연·평균·상위 지연을 뜻하지 않는다.
- 가상 대사 전체를 모아 검사하던 비교 경로는 발화 종료 후 약 12.6초였다. 사용자 선택에 따라 이 대기 경로를 기본 음성 연습에서 제거했다. 별도 Whisper·텍스트 생성·의미 검사·TTS를 정상 가상 대사마다 호출하지 않는다.
- 최신 에뮬레이터에서 마이크 입력을 끈 채 연습 시작 → Live 가상 인사 → 재생 상태·Android 활성 AudioTrack → 일시정지 → 종료 → 사후 체크를 확인했다. `.tools/stream-ui.json`, `.tools/stream-audio-state.txt`. 새 앱 프로세스의 경고·오류 및 현재 이벤트 로그에서 새 ANR은 확인되지 않았다. 실제 사용자의 음성 품질 검사를 대신하지 않는다.
- 앞선 전후 체크 연결 검사에서 사전 응답 → 마이크 시작·쉬기·재개·종료 → 사후 응답 → 그래프 → 테스트 기록 삭제를 확인했다. `.tools/continuous-ui.json`.
- 서버는 매 PCM 조각마다 DB를 조회하지 않고 정책 조회·버전 확인에 필요한 시점에 조회한다. 서버 음성 조각을 약 160ms 이상 묶어 전달하고, 네트워크 전송 대기·앱 초기화 대기·재생 대기·메모리 이력에 상한을 뒀다. 기록 목록은 20개씩 표시한다. 기존 3D 프레임·해상도 제한은 유지한다.
- `patch-audio-echo.mjs`가 Android 통신용 마이크와 지원 기기의 AEC를 재현 적용한다. 하드웨어 지원·실제 스피커 반향 제거·끼어들기 품질은 휴대폰별 직접 시연 과제다.
- 최신 모바일 TypeScript 검사를 통과했다. 앞선 중단·VAD 검사 7개와 서버 검사 12개가 통과했으며, 기존 검사를 불필요하게 반복하지 않고 새 스트리밍 경로를 별도로 확인했다. 두 아키텍처 APK의 서버 비밀값 미포함 검사를 통과했다. 기기별 메타데이터는 `artifacts/first-step-mvp-phone-verification.json`, `artifacts/first-step-mvp-emulator-verification.json`이다.
- `실행.bat`은 연결된 휴대폰 한 대를 우선 사용하고 없으면 에뮬레이터를 실행한다. `휴대폰실행.bat`은 USB 휴대폰만 실행한다. 같은 로컬 주소·포트로 HTTP와 WebSocket을 사용하며 별도 공개 포트를 열지 않는다.

## 이전 턴 방식 검증 기록

- 서버 JUnit 11개 통과: 도메인 10개와 실제 프로젝트 DB를 사용하는 Spring 컨텍스트 1개. 최신 결과 `.tools/server-final-test.log`.
- 모바일 TypeScript 검사와 중단 세대 관리 테스트 3개 통과.
- 실제 API 검사: 공고 노출, Gemini 전송 동의, 다른 세션 접근 거절, 중복 중단/재개, 공식 사실과 미확인 정보 분리, WAV 응답, 지연 응답 폐기, 세션 삭제, 선호 후보 근거와 사용자 확인 통과. `.tools/final-api-smoke.log`.
- 실제 공급자 응답 시간은 한정된 예시일 뿐이다. 최신 공식 날짜 질문 약 8.8초, 준비물 미확인 질문 약 6.6초에 TTS까지 응답했다. 기기·네트워크·할당량에 따라 달라진다.
- 가상 인사 `안녕하세요.`에 대한 실제 역할 대사·표현 검증·음성 응답이 통과했다. `scripts/verify-conversation.py`와 `.tools/conversation-final.log`에 해당 검증을 남겼다. 공급자에서 간헐적 HTTP 503을 실제 확인했으며, 전체 20초 범위 안에서 1회만 재시도한다. 429 할당량 오류는 자동 재시도하지 않는다. 재시도도 사용량 제한에 포함한다.
- 실제 앱에서 공식 공고 → 상세 → 연습 동의 → 3D 아바타 → 자막·음성·립싱크를 확인했다. 별도로 오류 시 단순 화면의 음성 재생, 멈춤/재개, 종료/결과 화면도 확인했다. 화면 기록은 `verification/06-avatar-local-model.png`, `verification/08-3d-speaking.png`다.
- 사용자 음성은 사용하지 않았다. 호스트 마이크 입력을 끈 채 Android 일회성 녹음 권한 요청과 권한 창 전환 시 중단을 확인했다. 이미 허용한 권한은 재요청하지 않도록 수정했다. 실제 녹음 파일을 업로드해 `인식 문장 확인`과 `인식된 말이 없어요` 안내가 표시되는 것을 확인했다. 결과를 AI에 자동 전송하지 않는다. 실제 사람의 발음·주변 소음·저사양 휴대전화는 검증하지 않았다.
- 인증·MIME·잘못된 파일·무음·65초 제한 STT 검사가 통과했다. `scripts/verify-stt.py`로 재현할 수 있다.
- 최종 APK의 구성된 서버 비밀값 미포함 검사를 통과했다. `artifacts/apk-verification.json`에 크기·SHA-256·아키텍처를 기록했다. 실제 APK 네트워크 XML에서 기본 HTTP 차단과 두 로컬 주소만의 예외를 확인했다.

## 정확성과 데이터 처리

공식 정보는 확인한 근거 ID를 서버에서 조회해 문장을 구성한다. 준비물처럼 근거가 없는 질문은 확인 필요로 처리한다. 이전 텍스트·턴 방식은 의미 검사 후 합성한다. 최신 Live 가상 대사는 사용자의 선택에 따라 스트리밍으로 재생하며 전체 사전 의미 검사를 하지 않는다. 지침·표현 감시·정책 질문 분리도 AI 오류나 분류 누락 가능성을 완전히 제거하지 않는다.

실제 공고가 1건이어서 여러 공고 사이의 추천 품질은 실데이터로 비교하지 못했다. ‘가장 통과하기 쉬움’이라는 확률·확정 문구를 사용하지 않는다. 공식 참여 부담 지표가 모자라면 그 사실을 안내한다.

이용자 자료는 DB에 보관하지 않는다. 메모리 세션은 비활동 30분/최대 120분에 만료하고 음성은 최대 120초 후 제거한다. 세션 삭제·프로필 수정·후보 삭제로 해당 자료를 제거한다. 공급자의 데이터 처리 범위는 [Gemini 약관](https://ai.google.dev/gemini-api/terms)을 따른다. 현재 실제 이용자 데이터로 사용하지 않는다.

별도로 저장을 선택한 전후 상태 응답은 단말의 앱 전용 파일에 남는다. AI·서버로 보내지 않고 개인 기록에서 삭제할 수 있다. 기기 공유 시 계정 구분을 제공하지 않으며, 장기 대화·녹음 저장과 구분한다. Live PCM은 파일로 저장하지 않는다.

## 로컬 실행과 해결한 환경 문제

- 파일은 요청한 폴더에 유지하고 승인된 `P:` 별칭을 사용한다. Android 자동 연결 경로를 P:로 통일하고 CMake 객체 경로 길이를 제한했다.
- Windows 신뢰 인증서를 JDK/Node에 적용했다. 인증서 검증을 끄지 않았다.
- HTTP는 승인된 `10.0.2.2`·`127.0.0.1`만 허용한다. 공개 서버는 HTTPS를 사용해야 한다.
- WebView의 `fetch(file://)` 실패를 확인해 번들에 포함된 GLB·립싱크 모델 두 파일만 로컬 XHR로 읽는 어댑터를 추가했다. 외부 모델 서버나 사용자 입력 코드는 사용하지 않는다.
- SDK가 만든 로컬 오디오 모듈에 필요한 `blob:` 스크립트 정책을 적용했다. [Worklet 모듈 로딩 문서](https://developer.mozilla.org/en-US/docs/Web/API/Worklet/addModule), 설치된 SDK의 `audioContext()` 구현을 함께 확인했다.
- Expo 58의 fetch 구현은 기존 React Native의 `{uri}` 멀티파트 파일을 지원하지 않았다. 설치된 `convertFormData.ts`에 맞춰 `expo-file-system`의 `File` 객체를 직접 업로드한다. 녹음 파일은 요청 완료·중단 시 제거한다.
- 에뮬레이터는 이 PC에서 호스트 GPU와 메모리 4GB로 점검했다. 다른 환경은 `start-emulator.ps1 -Gpu swiftshader` 옵션으로 별도 확인할 수 있다.
- 사용자가 승인한 `.env` 설정을 복구했다. API 키는 유지했으며 DB 포트·무료 시연 모델·STT 내부 인증 설정을 맞췄다.
- 사용자는 직접 가상 대사를 말하는 시연을 위해 PC 마이크 입력 연결을 승인했다. 자동 검증에서는 마이크를 끄고, 직접 시연용 실행 스크립트에서는 연결한다. 제출용 시연 영상은 이번 작업에서 제작하지 않았다.
- `scripts/run-demo.ps1`은 로컬 서비스·에뮬레이터·APK 설치·승인된 마이크 연결을 한 번에 실행한다. `-KeepMicrophoneOff`로 마이크 연결을 제외할 수 있다. 키를 명령행 인수로 전달하지 않는다.
- 이후 실제 사용에서 WebView 렌더링 대기로 인한 ANR이 확인되어 그래픽 설정과 모바일 렌더링 프로파일을 보완했다. 소프트웨어 GPU를 기본값으로 채택하지 않았다. 현재 실행 기본은 호스트 GPU·Vulkan 비활성화·720×1280 / 280dpi다. 원인 근거·짧은 CPU 표본·검증 범위는 [RENDERING_PERFORMANCE.md](RENDERING_PERFORMANCE.md)에 정리했다.
- 최종 APK에서 키보드 표시 시 아바타가 내려가고, 멈춤·종료 버튼의 하단이 키보드 상단보다 위에 있는 것을 좌표로 확인했다. 키보드 복귀·아바타 재표시·연습 종료도 확인했다. 이후 검사 구간에 새 ANR 기록은 없었다.

## 공유 검사와 저장 안정성

- Windows 격리 설치와 GitHub 별도 호스트 검사를 진행했다. 범위와 한계는 [공유와 새 환경 검사](SHARING_AND_TESTING.md)를 따른다.
- Expo 파일의 쓰기·복사가 비동기인 것을 확인해 기록 저장·삭제, 음성 재생·전송 전 파일 생성, 아바타 자산 복사 완료를 기다리도록 수정했다. 에뮬레이터에서 0점 응답 보존과 삭제 직후 목록 갱신을 확인했다.

## 남은 작업

새로 확정한 기능 개발 → 실기기 통합 확인 → 전체 병목 최적화 순서로 진행한다. 관리자 기능은 남은 구현 작업에 포함하지 않는다. 상세 목록은 [기능 변경과 미해결 과제](FEATURE_BACKLOG.md)를 따른다.

1. 온통청년 인증키 수령 후 최신 API 명세에 맞춰 동기화·변경 감지 구현.
2. 공식 공고 추가와 기관의 준비물·자격·시간 확인. 실제 추천 품질 비교.
3. 실제 이용자 도입 전 데이터 처리 방식·휴대전화·접근성·사용성 검증.
